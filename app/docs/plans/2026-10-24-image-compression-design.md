# TinyPNG Local 界面设计

用户确认采用浅色 macOS 风格。沿用 NSH + Rust 原生项目。

## 目标与边界

让用户清楚完成添加图片、检查队列、压缩、查看节省体积四个步骤。
当前只提供真实可用的 PNG 无损优化；质量滑块、JPEG/WebP 转换、自定义输出目录不在本轮范围内。
不引入新的 UI 框架或网络服务。

## 视觉与结构

- 1180 × 800 默认窗口，原生窗口控制区，浅暖灰背景与森林绿强调色。
- 左侧 190 pt 导航：全部图片、待处理、已完成，计数跟随队列。
- 中间主区：标题、浅绿色拖拽区、图片列表、固定底部统计和压缩操作。
- 右侧 256 pt 信息区：无损优化、原始尺寸、保存位置、本次节省体积。
- 1080 pt 以下隐藏右侧信息，840 pt 以下隐藏导航，优先保留导入与压缩主流程。
- 空队列不填充虚构图片与统计。导入后展示真实缩略图、名称、大小与状态。

## 交互与数据

支持文件面板多选、PNG 拖入、同路径去重、移除队列项、清除已完成、失败后重试。
压缩期间锁定队列变更，以开始时的队列快照计算进度。
输出到原图目录内的 compressed 子目录；已有同名输出增加序号。
使用生成的原生类型读取 camelCase 结果字段。
PNG 直接经过 oxipng，保留透明度与像素。优化后更大时输出原始 PNG 数据。

## 验证

以类型检查、空状态与分类交互测试、原生窗口截图，以及透明 PNG 的像素一致性检查为准。
本轮不增加发布、自动更新或服务端能力。

## 已执行验证

- `nsh check`：通过。
- `nsh test`：空状态、分类切换与窄窗口布局交互通过。
- Rust RGBA 回归测试：像素一致、原图不变、输出不增大。
- 原生窗口实测：文件选择与压缩成功，实际样例约节省 26%。
- 原生批量测试：三张生成的 PNG 均完成，缩略图与文件大小统计已截图核对。
- `design/tinypng-batch.png` 使用未压缩的测试图案展示界面；图中高压缩率不代表普通图片的典型效果。
- macOS `.app` 已构建。文件面板调度到主线程；文件权限限定到用户目录、临时目录和外接卷；缩略图使用原生支持的绝对路径。
