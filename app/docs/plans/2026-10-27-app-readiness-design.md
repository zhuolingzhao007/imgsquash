# App 可用性收尾

复杂度 L3：文件边界增加资源准入，队列增加停止与重复执行语义。用户已授权完成可用性审查中列出的项目。

后续大图改造已替换单图拒绝策略，当前行为以[大图设计](2026-10-27-large-image-design.md)为准；下方完成记录保留当时验收证据。

## 目标与边界

普通图片的添加、压缩、失败重试、查看输出形成稳定闭环；压缩文件很小但像素很多时，也不能绕过内存保护。停止不能破坏正在保存的结果，重压不能把上次输出当原图。核心率失真策略及每条有损路径最多两个全图参数保持不变。

## 方案选择

方案 A：TS 预读尺寸、按权重调度；优点是等待状态直观，缺点是原生直接调用可以绕过保护、文件变化后估计会失效。方案 B：Rust 文件边界统一按像素量准入；所有调用共享资源预算，TS 只限制任务数量并处理停止。选择 B，避免在两层复制资源策略。

不强杀单图编码线程；停止只阻止领取新任务，已领取任务完成、保存后结束。相比逐阶段植入取消信号，这个方案无需侵入多个编码器，语义也能明确呈现给用户。

## 职责与流程

- `resources.rs`：内存估计、预算、并发准入与 RAII 释放。预算按物理内存四分之一取值，限制在 128 MiB–4 GiB；查询失败使用 512 MiB。估计包含像素缓冲、感知测量的多组浮点平面、输入和编码工作区；它不是操作系统强制内存上限，也不读取其他 App 的即时占用。
- `squash::compress_file`：打开同一个文件句柄，先读取有界图片头并选择实际路径，再申请资源，校验文件未变、编码与保存。超出常规预算或输入超过 128 MiB 时走扫描线，无损或原样复制兜底。
- `state/pool`：领取任务前检查停止条件。`state/compression`：批次锁、停止信号、进度与重压目标。停止后未启动图片保持原状态；重压用原路径和当前设置，旧输出保留。
- `FilePicker`：图片和文件夹使用明确独立入口；macOS 文件夹面板不设置图片类型过滤，Windows 使用 `pick_folders`。复用现有递归扫描。
- 导入预览也受保护：仅列表前 32 项中不超过 1 MP 的图片加载原生预览，其余显示图标。PNG 尺寸只解析 IHDR，JPEG 流式跳过标记段查 SOF；不为尺寸探测先读取整份 JPEG 或解压 PNG 的 ICC。
- 发布、仓库、证书、签名、公证均按用户后续指示排除，本轮不修改这些流程。只构建本地验证包。

## 验证信号

资源测试覆盖超预算、并发等待和释放、尺寸/文件长度变化；队列测试覆盖停止、继续、重压原图与不覆盖输出。增加渐变、透明边缘、纹理、照片与色彩配置样本的 release 验收和可视化产物；指标不能代替主观画质验收。最后实际操作新的 macOS 包验证文件夹导入、停止、重压与 Finder 定位。

## 设计检查

资源策略只在 Rust 文件边界执行，编码器无需了解队列。调度不识别编码格式；新增格式复用同一文件准入。删除资源组件会失去跨原生调用的内存协调，删除停止检查会继续启动队列；保留这两个机制，其余复用现有函数，不引入任务框架、协议或额外线程池。

## 完成结果与证据

- 删除原来按最大输入超过 8 MiB 就限两路的启发式，改为像素量资源准入。测试验证不足 1 KiB、声明百万乘百万像素的 PNG 在解码前被拒绝；超过 128 MiB 的稀疏文件在读取前被拒绝；任务等待和异常退出会释放预算。
- 停止只阻止领取下一项。原生窗口中 8 张 UI 图停止后恰好生成 4 份 83,591 B 输出，其余 4 项待处理；继续后输出总数恰好为 8，没有重复处理。
- 换严格档从原图重压后生成另外 8 份 88,613 B 结果，所有旧结果及原图字节不变。重压批次启动时把选中项标为待处理，保留旧输出路径；停止后可只继续剩余项。这一点也包含在集成测试内。
- 文件夹面板的「添加」按钮实机可用，14 个输入正确入队，跳过 `compressed`；13 个正常图片完成，超大尺寸项单独报错，不影响整批，无错误输出文件。
- 增加桌面权限上下文内的 `WorkflowApp.tsx` 集成入口，覆盖目录扫描、双击启动、切换模式、重压、输出删除后重压、停止重压和继续；它仅供测试，生产 App 不导入。没有扩大 `nsh.json` 的权限。
- 核心 38、应用 Rust 54、TS/原生交互 26 项检查通过，总计 118 项；完整 `nsh test` 先通过 79 项，新增格式设置测试及后续队列修正再通过对应 Labels/App/Workflow 检查。三个默认忽略项是两个历史基准和本次显式实图验收。`nsh check`、两份 Clippy 严格检查、格式和 diff 检查通过。
- `scripts/quality-check.sh` 本机 release 验收 9 类、54 份输出通过；CSV 和原图/结果保存在 `.nsh/out/quality`。渐变、透明边缘、纹理、16 位与 ICC/P3 边界均已覆盖；原格式严格 UI 仍为 88,613 B。没有因测试扩展放宽任何画质预算。
- 新本地包位于 `.nsh/out/readiness/imgsquash.app`，已启动并操作验证。这里只证明本机 macOS 行为；Windows 新分支尚无 Windows 实机验证。P3 的数字评分仍采用 sRGB 假设，保留配置的验收不等于验证色彩管理准确性。也不将这组有限样本宣称为系统主观画质实验。

关键取舍：资源估计有意偏保守，后续已用低内存与原样复制替代仅因工作集超预算而拒绝大图的行为；停止会等待最多四个已提交任务，换取编码器和落盘路径无需强制中断；重压保留旧文件，磁盘占用会增加。无需加入缓冲池、结果缓存或新的压缩候选机制。
