# 大图处理：有界内存与流式压缩

L3，用户授权落实五项优化；不包含发布、仓库、签名或公证。

## 目标

大图不能仅因完整智能路径的保守估计超预算而被拒绝。保持尺寸，保留原图，不增加最多两次全图参数预算；质量或收益不满足时安全退回无损/原文件。

## 方案与取舍

放宽全图内存上限改动少，但不能消除随像素增长的 RGB、XYB 和方差缓冲；仅将评分分块仍需持有原图和候选图。采用普通路径与低内存路径组合：先检查格式语义和实际处理计划，正常尺寸复用现有流程，大图按行解码到自动清理的磁盘像素文件，再以有界块建直方图、采样、映射、编码和验证。

临时文件增加磁盘读写，换取像素工作集不随图片高度增长；JPEG 渐进解码仍可能需要整幅系数缓冲，必须单独估算，超预算时流式复制原文件。WebP 当前编码器需要整图像素，低内存路径不强行转换。

## 边界

- 文件计划负责原样保留、常规内存路径、流式 PNG/JPEG 的选择；资源组件只负责预算与准入。
- 量化组件提供有界映射缓存，普通流程也复用；流式直方图仅从最多 262,144 个分层采样像素学习；无抖动映射保持像素结果可复核。流式路径不在块边界重置误差扩散来伪装等价。
- 像素临时文件负责按行写入和按区域读取，不制定质量策略；流式编码器不管理队列。
- 评分提供重叠、全覆盖的分块验证。最低结构分、最差局部误差用于大图保守验收；它不是整图 SSIMULACRA2，API/UI 明确记录类型。使用当前档位预算约束每一块，并用固定语料对照整图验收；不声称数学等价或普遍保证。
- 最终候选预算和收益判断复用现有机制，输出临时文件直接安全发布，不把大文件重新读入 Vec。

## 验证

先保护原有严格 UI 88,613 B 回归；新增有界颜色缓存与原映射逐像素对照、文件计划分流、PNG 8/16 位/调色板/元数据/交错、JPEG 扫描线与方向语义、分块边界/局部损伤、失败回退和 no-clobber 测试。固定语料比较分块与整图决策，真实大图记录输出尺寸、体积、耗时和峰值 RSS。损坏输入必须报错或明确原样保留，不能发布半成品；临时文件由 RAII 清理。


## 实现与资源边界

- `file_plan` 将容器语义和路径选择放在资源申请前。低质量/受保护 JPEG 直接复制；16 位、索引 PNG 或灰度 ICC PNG 不按完整智能路径估计。128 MiB 仅限制整文件读入内存；超过后走文件流程。
- `resources` 只做共享额度准入。普通路径保留 192/48 B 每像素规划；流式有损/无损为 192/32 MiB 加行宽×64 B，渐进 JPEG 再加 16 B 每像素的系数余量。流式也放不下时降级，无需让预算机制了解格式规则。
- `raster` 使用关闭后自动删除的系统临时文件。PNG 有损约需 9 B/像素的同时存活磁盘空间，JPEG 约 8 B/像素，另有目标目录内的编码文件；空间不足会报错。普通流程继续使用 Arc 与 Vec，文件产物由 `Candidate<T>` / `Payload` 复用同一最多两次的验收机制。
- 颜色映射缓存最多 65,536 色；超过后直接分批映射，普通无抖动结果逐像素相同。流式颜色学习用最多 262,144 个分层采样像素，调色板在行之间复用，不使用按行重置的误差扩散。
- 流式搜索使用最多三个 128px 原尺寸块（左上、中部、右下），与普通路径按渐变/纹理/边缘选择的样本不同。代表性不足可能造成保守回退或遗漏更好参数，不能省略最终全覆盖验证。
- 分块使用 512px 窗口、384px 步长，起点按 8 对齐；通过必须覆盖所有像素，拒绝可提前结束。类型 `TiledMetrics` 的最低分明确不是全图 SSIMULACRA2；API 的 `scoreKind=tiled` 与队列「分块最低」同步。
- 扫描线 PNG 保留 Adam7、packed palette/tRNS、16 位、ICC 等语义；快速无损基线与均衡索引编码不再套全文件 oxipng。为保护原位深，PNG 无损基线和有损 RGBA 路径分开按行读取，接受额外磁盘 IO。
- 扫描线 JPEG 使用 `set_fastest_defaults`，关闭 trellis、渐进和 Huffman 优化。确认 vendored `jcinit.c`：上述任一优化均可能要求全图系数。采样和全图共用编码设置，固定 ICC/EXIF 字节不按像素比外推。已编码且节省不足时通过独立的 `Trial::Unprofitable` 跳过解码和评分，不伪造质量度量。
- JPEG 头部 APP1/2/13/COM、方向标记、JFIF 密度保留；方向不烘入像素。严格解码将负级别警告升级成失败，避免截断文件被静默补齐后发布。相同文件尺寸/ICC/核心元数据回读与源文件时间/长度核对后，仍用原有 no-clobber 发布。
- WebP 缺少可用的有界像素编码入口，因此低内存路径保持实际 PNG/JPEG，给出原因；不引入另一个编码器或结果缓存框架。

## 完成验证

核心 41、应用 Rust 62、TS/原生调用 27，共 130 项通过。`nsh check`、两份 Clippy `-D warnings`、格式检查通过。本地 macOS 包构建到 `.nsh/out/readiness/imgsquash.app`。桌面权限内的 Workflow 自动化覆盖导入、队列停止/继续与重压；手动大图窗口验证时 CUA 对清单中运行的应用持续返回 `Invalid app`，因此不声称完成该项手动 UI 验收。Windows 尚无实机验证。

新增回归包含：超过 128 MiB 的有效 PNG 可处理；低预算原样复制且不覆盖；源文件变化拒绝发布；普通量化缓存截断与直接映射逐像素对照；Adam7 RGBA、16 位灰度、1 位索引透明度、eXIf/ICC；JPEG 方向、密度、样本/扫描线码流相同、截断数据拒绝；分块边缘损伤和提前拒绝必须标记未完成。原有严格 UI 仍输出 88,613 B。

固定 9 类/54 份结果新增全图/分块对照。53 个通过分块，1 个严格 UI PNG 因最低块分 85.87 低于 88 被拒绝，而全图 88.35 通过。这证明分块有额外保守性；这组语料未出现分块放行而全图拒绝，不能推出任意输入下等价。CSV 增加 `min_tile_score`、`tile_accepted`，结果与并排查看页在 `.nsh/out/quality`。

独立 release 进程使用 `/usr/bin/time -l` 记录 RSS；以下耗时只计压缩，RSS 含生成和回读测试。8000×6000 的双色 PNG：946,715 → 17,347 B，1.73 秒、峰值 12,369,920 B；逐行重新解码验证全部 48MP 的 RGBA 像素相同。6000×4000、由现有照片平铺生成的 JPEG：标准档 8,396,840 → 4,720,927 B，q84、分块最低 79.0561、6.34 秒、峰值 87,949,312 B；更小档 3,547,857 B，q73、最低 70.2504、6.35 秒、峰值 89,079,808 B。均保留尺寸；两份 JPEG 各只用一个全图参数。

阶段数据表明，JPEG 的行解码/编码约 0.1 秒量级，评分约 5.96/5.99 秒。低内存并不意味着全覆盖验证无需随像素增长；不通过降低质量预算来追求速度。早期 21 秒/约 218 MiB 的实验含默认 trellis，且输入造图配置不同，只作为发现隐藏整图缓冲的诊断，不作同输入性能对比。

复现命令：

```sh
cargo test --release --lib --no-run
# 使用上一步实际输出的测试可执行文件；不要把 cargo/编译器内存算进 RSS。
TINYPNG_PROFILE=1 /usr/bin/time -l <test-executable> bench_48mp_streaming --ignored --nocapture
TINYPNG_PROFILE=1 /usr/bin/time -l <test-executable> bench_24mp_jpeg_streaming --ignored --nocapture
TINYPNG_LARGE_PRESET=smaller TINYPNG_PROFILE=1 /usr/bin/time -l <test-executable> bench_24mp_jpeg_streaming --ignored --nocapture
./scripts/quality-check.sh
```

设置 `TINYPNG_LARGE_OUT` 可保存基准原图和输出；默认临时目录在测试结束后清理。

## 设计复核

路径策略只在文件计划，准入不依赖 JPEG/PNG，磁盘像素不决定质量阈值，编码器不管理队列。新增实际文件产物只需实现 `Payload`，无需复制两次预算和收益判断；现有 Vec 仍走相同机制。删除 `Payload` 会复制两条完整验收循环，删除 Raster 会在编解码和评分之间泄漏临时文件偏移约定；这两处保留，其余直接函数调用，没有新增策略协议、线程池或包装层。普通流程与低内存流程只在资源/IO 模式和验收指标上分开，不在普通路径引入磁盘成本。
