# 首次全图失败后的样本偏差校准

L2：保留最多五次采样探测、每条有损路径最多两个全图参数，保留现有档位和验收标准。变化集中在样本记录、首次失败反馈与第二次选点；原有未提交的成本选点、局部上限和渐变采样改动继续保留。

## 先确认失败原因

输入为 `design/layout-1180.png`，2360×1600，严格档。以下是修复前诊断，同一行的样本值使用同样本快速无损参照：

| 颜色数 | 样本字节比 | 样本 D | 样本局部 RMSE | 修复前全图 D |
| --- | --- | --- | --- | --- |
| 256 | .67703772 | .04887690 | 3.184435 | .12652662（旧次选） |
| 136 | .62794807 | .06216236 | 4.233424 | 未尝试 |
| 76 | .52308520 | .10972515 | 13.757952 | 未尝试，样本结构预算未通过 |
| 106 | .59606668 | .06967746 | 4.990616 | 未尝试 |
| 91 | .55696397 | .07092619 | 5.040461 | .12040447（首选） |

严格档全图 D 上限 .12、独立局部 RMSE 上限 24。91/256 色的全图局部误差分别为 22.190581/21.450160，均通过；两者因 D 超限在 PNG 编码前被拒绝。没有执行最终体积、最低节省 3% 或 C<1 的判断，不能把此例归因为节省不足或成本权重过于保守。

## 为什么只对原样本乘一个 k 不够

原样本得到 `k_D=.12040447/.07092619≈1.69760239`、`k_local≈4.40249037`。按它修正其余候选，256 色预测 D=.08297354、成本约 1.091905；136 色预测 D=.10552697、成本约 1.155583。二者预测质量都通过，按成本仍然会选 256 色，而它实测失败。

同一图的不同调色板可能产生不同方向的结构失真，不能从一个点推出所有参数都共享原样本倍率。用户确认允许补充受损区域的小块评分，但不增加全图预算，因此采用以下方案。

## 当前流程

1. 搜索保留全部已探测点的字节数、字节比、实际度量及可行成本。即使某点最后未通过样本结构/局部预算，已经计算的度量也保留；前两级廉价过滤未通过时不追加 SSIMULACRA2。
2. 第一参数仍按样本成本选择。全图验收返回实际 Metrics；PNG 在编码前质量拒绝时使用结构化 `Trial::Rejected` 返回度量，不将它丢成普通字符串错误。
3. 只有全图质量失败才校准。若只是编码故障、最低节省不足、C≥1，或首选成功且前两名近似平手，则沿用原次选，不把收益问题当作质量偏差。
4. 对 PNG 非抖动、多参数路径，在现有全图可见误差扫描中累计 128×128 区域误差能量，选择平均可见平方误差最大的区域。记录区域坐标与大小，不再扫描一遍整张图；边缘区域向内夹取，保证有效尺寸。
5. 首选失败后，对原来探测过的参数在同一受损区域做小块评分。复用全图直方图与已缓存调色板，只映射/评分小块，不编码新的全图，也不增加颜色数探测。
6. 将受损区域作为校准样本：`k_D=首选全图D/首选区域D`，局部误差单独计算倍率。预测其他参数的全图 D 与局部误差，剔除超出全图预算者，再以原有样本字节比加权预测 D 排序，选择第二参数。JPEG/WebP 使用已有样本校准，不增加小块编码路径。
7. 若预测无可行参数，直接回退；若第二参数失败，也直接回退。所有最终输出必须通过真实全图质量、真实字节数、最低收益与 C<1 验收，预测结果不能代替验收或写入最终评分。

当前只增加一处受损区域。局部误差与整体 D 的倍率分别计算；倍率允许小于 1，因为受损区域可能比整图困难。样本误差为零时不能做除法，使用已观察到的绝对偏差作为保守加法修正，避免 NaN/无穷。复核时所有参数必须使用同一块区域；缺失区域度量的点不与原样本值混用。若连首选区域度量都无法获得，使用原样本的校准路径。

样本字节比是排名估计，不能用预测 C≥1 提前拒绝候选。此例 136 色的预测 C≈1.227716，但真实全图 C≈.986865；最终收益只用实际编码结果判断。

## 实图结果

第一全图仍为 91 色，D=.12040447，不通过。受损区域是 `(512,640,128,128)`：

| 参数 | 受损区域 D | 校准后的预测全图 D | 第二次可行性 |
| --- | --- | --- | --- |
| 91 | .23092523 | .12040447 | 首选已尝试，不重复 |
| 256 | .27045712 | .14101641 | 超出 .12 |
| 136 | .23006038 | .11995354 | 通过 |
| 106 | .23047149 | .12016789 | 超出 .12 |
| 76 | .24819970 | .12941138 | 超出 .12 |

`k_D≈.52140024`，`k_local=1`。第二全图改选 136 色，实测结果：

- 有损 PNG，**88,613 B**，感知分 **88.3462**。
- 实际全图 D **.11653792**，局部 RMSE **21.969795**。
- 真实无损基线 **219,244 B**，实际字节比 **.40417526**，节省 **59.5825%**。
- 实际 C **.98686483<1**，最低节省 3% 通过。
- 全图参数依旧两个：**91 → 136**。五个小块的映射/评分合计约 **14 ms**，仅首次质量失败时执行。

以上为本机 release 单次诊断，不是所有图片的性能保证。此模型仍是预测，无法保证其他图片每次都找到可行候选；安全性依赖最终全图验收和无损回退，而非放宽预算。

## 回归与边界验证

`strict_ui_stays_lossy_within_ten_percent_of_the_previous_result` 将实际 UI 图片嵌入测试，断言有损、评分至少 88、输出 ≤88,613×1.1（97,474 B）。它在修复前失败、修复后通过。

另外验证：重新选择原次选以外的参数、没有预测候选时只执行一次全图、零样本误差、局部/整体独立倍率、同一复核区域约束、仅收益失败不校准、近似平手复核、编码故障和重复参数的尝试上限，以及图像边缘区域的合法坐标。

完整检查通过：核心 38 项；`nsh test` 70 项通过（48 Rust + 22 TS），2 项基准默认跳过；总计 108 项非基准测试。`nsh check`、两个 crate 的 Clippy `--all-targets -- -D warnings`、格式检查与 `git diff --check` 通过。

真实 UI/照片分别在原格式和 WebP 的三个档位显式跑过 release 基准。严格 UI 恢复为 88,613 B，单次约 2.53 秒；其他组合的字节数和评分与本次校准前保持相同。窗口、文件写入和格式保护已有回归继续通过；Windows 原生运行、打包和完整人眼验收没有在本轮执行。

## 设计取舍

- `quality` 产出度量和损伤区域；不决定质量偏好，不做候选编码。
- `search::Plan` 保留样本、完成纯预测与重新排名，不识别 PNG/JPEG/WebP。
- `pipeline` 区分编码失败、质量拒绝和收益拒绝，并持有两次全图预算。
- PNG 适配层利用已有调色板能力补充区域观测，其他格式复用普通倍率校准。没有新增协议、线程池、全局缓存或模型训练流程。
- 删除校准机制会回到已经证实会选错的 256 色；删除区域观测只保留统一倍率仍不能通过此例。两者都保留，但不增加第三次全图尝试。
